# ADR-0001：建设证据优先的应用框架

- 状态：已接受
- 日期：2026-09-15

## 背景

原 DUTMed 项目验证了一些值得保留的方向：医疗领域 Schema、Neo4j 关系检索、上传文档溯源、多跳搜索和医疗安全分流。但其实现将入库、检索、生成、界面、模型调用和基础设施集中在少数模块中，后续难以独立测试和替换。

现有开源项目已经提供了成熟的底层能力：

- 编排框架负责连接模型、工具和检索器；
- 数据框架负责连接器、索引和查询引擎；
- GraphRAG 实现负责知识图谱构建与检索算法；
- 应用平台负责可视化工作流和知识库界面。

如果重新实现上述所有能力，项目只会变得宽泛，不会形成真正的差异化。

## 决策

TraceGraph 将建设为一个代码优先、面向专业知识库证据生命周期的应用框架。

其稳定核心负责定义：

- 可追踪证据和主张到证据的关系；
- 回答、拒答、冲突、升级处理和系统错误等结构化状态；
- 将 Schema、策略和评测行为组合在一起的领域适配器；
- 可以提升为回归评测案例的用户反馈。

具体基础设施位于这些契约之后。v0.1 只实现一套可工作的技术组合，不宣称支持所有模型和数据库。

DUTMed 医疗领域是第一个参考实现，不进入通用核心层。

## 结果

### 积极影响

- 核心行为无需 LLM、Neo4j 或网络即可测试；
- 回答可以追踪到主张、文档版本、Chunk 和图路径；
- 领域安全规则和评测规则不会散落在提示词中；
- 新检索技术可以在稳定的 Evidence 契约后进行比较。

### 权衡

- 首版集成数量会少于通用框架；
- 主张级溯源比在答案末尾简单添加引用需要更多结构化数据；
- 领域适配器需要经过整理的 Schema 和评测案例，不能只更换提示词。

## 延后决策

- Agent 与工具调用架构；
- 医学影像处理和 FastSAM 迁移；
- 多租户权限；
- 第二套生产级存储后端；
- 公网部署与敏感数据治理。

只有当文本版 DUTMed 参考应用及其评测 baseline 可以稳定运行后，才重新讨论这些问题。
